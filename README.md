# Python Course

Учебный репозиторий: путь от нуля до уровня Junior Python backend-разработчика.

## Цель

Научиться понимать и писать код на Python, читать документацию и сообщения об ошибках, проверять решения тестами и обосновывать их. Пройти путь от учебных примеров к работе по техническому заданию, собрать портфолио и подготовиться к собеседованиям.

## Документы

- [PROGRESS.md](PROGRESS.md): текущий статус, слабые места, текущий проект, история уроков.

## Методика

Три режима работы:

1. **Обучение**: объяснение, пример, практика, проверка.
2. **Практика**: дано условие и ожидаемый результат, подход выбираю сам; чтение, исправление и рефакторинг чужого кода.
3. **Разработка**: итоговый проект по требованиям и критериям приёмки, ревью кода и тестов.

Как устроен урок:

- урок делится на 3–6 частей, части выдаются по одной;
- в конце урока: конспект и 3–5 задач (2–3 обязательные и дополнительные);
- каждые 3–4 урока: контрольная без подсказок;
- с модуля 2: разминки на 10–15 минут раз в 2–3 урока, с урока 11 с оценкой Big-O;
- с модуля 3: вопросы как на собеседовании в конце каждого модуля;
- урок завершён, когда пройдены все части и проверены обязательные задачи.

## Правила Git

- Коммит делаю после реальных изменений, небольшими осмысленными шагами.
- Сообщения коммитов пишу по [Conventional Commits](https://www.conventionalcommits.org/):
  - `feat`: новая функциональность или решение задачи;
  - `fix`: исправление ошибки;
  - `docs`: документация, прогресс, глоссарий;
  - `test`: тесты;
  - `refactor`: изменение кода без изменения поведения;
  - `chore`: служебные изменения (настройки, зависимости).
- Пример: `docs: add lesson 1 progress`.
- После коммита делаю `git push`, чтобы изменения появились на GitHub.
- Секреты (пароли, токены, `.env`) в Git не попадают, для этого есть `.gitignore`.

## Программа

### Часть 1. Фундамент Python (`part_1_foundation/`)

- **Модуль 1. Первый код и инструменты** (уроки 1–5): репозиторий и документы, первая программа, переменные и типы, ввод и вычисления, история в Git.
- **Модуль 2. Условия, циклы и коллекции** (уроки 6–12): условия, `while`, `for` и строки, списки, словари, кортежи и множества, идиомы Python.
- **Модуль 3. Функции, модули и ошибки** (уроки 13–16): функции, аргументы и область видимости, разбиение программы, ошибки и отладка.
- **Модуль 4. Данные, тесты и классы** (уроки 17–21): файлы и JSON, дата и время, окружение и тесты, классы, наследование и `dataclass`.

### Часть 2. Backend (`part_2_backend/`)

- **Модуль 5. HTTP и первый API на FastAPI** (уроки 22–27).
- **Модуль 6. SQL и PostgreSQL** (уроки 28–32).
- **Модуль 7. PostgreSQL в приложении** (уроки 33–38).
- **Модуль 8. Безопасность, качество и запуск** (уроки 39–46).
- **Модуль 9. Сервер и деплой** (уроки 47–48).

### Часть 3. Итоговый проект (`part_3_capstone/`)

- **Модуль 10. Сервис для портфолио**: ТЗ, план, реализация итерациями, тесты, деплой, ревью.

### Часть 4. Выход на рынок (`part_4_career/`)

- **Модуль 11. Портфолио и собеседования** (уроки 49–52): GitHub-портфолио, резюме и тестовые, подготовка, пробные собеседования.

## Критерии завершения курса

- Итоговый сервис по ТЗ реализован самостоятельно на Python, FastAPI и PostgreSQL.
- Схема БД ведётся миграциями; могу объяснить ограничения и транзакции на примере.
- Аутентификация и права доступа по ТЗ, есть тесты запрета доступа к чужим данным.
- Пагинация, фильтрация и сортировка по ТЗ, единый формат ошибок.
- Модульные и интеграционные тесты запускаются в CI.
- Проект запускается через Docker Compose из чистого клона, есть рабочая ссылка.
- На ревью объясняю устройство проекта и вношу изменение по новому требованию.
- Готовы резюме и портфолио, пройдены минимум два пробных собеседования.
